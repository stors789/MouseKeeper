# 备份与恢复

## 1. 备份的用途

完整 JSON 是 MouseKeeper 的灾难恢复格式。它保存当前 schemaVersion 下的全部 16 张业务表，包括软删除记录、关系历史、活动日志、保存视图、应用设置和备份元数据。CSV 只用于交换和报表，不能重建完整数据库。

建议在以下时间下载备份：

- 首次录入真实数据后；
- 大批量导入、转笼或状态调整前后；
- 恢复旧备份前；
- 浏览器、操作系统或设备升级前；
- 至少按实验风险制定固定周期，并把副本保存到另一块磁盘或受保护存储。

## 2. 导出完整备份

1. 打开“数据与安全”。
2. 选择“备份与恢复”。
3. 点击“下载完整备份”。Web/PWA 会发起浏览器下载；Tauri App 会打开系统保存对话框。
4. 确认文件实际落盘，并把文件保存到浏览器站点数据或 App 沙箱之外。

文件名形如 mousekeeper-backup-2026-08-01T05-20-30Z.json。导出过程在一个只读事务中读取全部表，生成规范化 JSON，并在下载前用与恢复相同的验证器重新校验。

备份信封包含：

- format 与 backupFormatVersion；
- schemaVersion 与 appVersion；
- exportedAt、backupId、databaseInstanceId；
- 16 张表的 tableCounts 和 data；
- SHA-256 canonicalPayloadDigest。

校验和只能发现内容意外变化，不能证明文件由可信人员创建，也不提供加密。

## 3. 恢复流程

恢复是“全部替换”，不是合并：

1. 先下载一份当前数据库的手工备份。
2. 在“备份与恢复”选择 JSON 文件。选择文件不会修改数据库。
3. 查看预检结果、导出时间、总记录数和逐表计数。
4. 只有预检通过时，输入确认短语“替换本地数据”。
5. 点击“执行恢复并下载安全备份”。
6. 保留浏览器下载的恢复前安全副本，确认恢复后的关键小鼠、笼位和记录。

恢复命令会在同一个全表写事务中先读取精确的恢复前状态并完成安全副本摘要，再清空和写入全部表。任一清表或写入失败会回滚整个事务。事务成功后，界面发起刚才封装的精确恢复前副本下载；若浏览器下载单独失败，界面会明确说明“数据已恢复、下载失败”，不会把数据库提交误报为失败。

请不要在恢复进行中关闭页面、清除站点数据或同时从另一个标签页修改数据。应用已尽量缩小并发窗口，但本地文件和浏览器生命周期仍由用户设备控制。

## 4. 恢复前验证

当前版本拒绝以下输入：

- 大于 100 MB、非 UTF-8、非法 JSON 或包含不安全对象键的文件；
- format 不匹配、未来 backupFormatVersion 或未来 schemaVersion；
- 缺少表、出现未知表、表计数不一致或 SHA-256 不一致；
- 重复主键、行字段不符合 Zod schema、记录 schemaVersion 不一致；
- 缺失父母、笼位、实验、组别、事件、体重或任务关联；
- 同一小鼠多个活动笼位、重复活动实验关系或 WeightRecord/MouseEvent 配对不一致；
- 日期、时间、快照、规范化键或关系投影互相矛盾；
- 谱系自引用或明显循环。

schemaVersion 低于当前版本的备份只有在代码提供显式内存迁移时才能恢复。v0.1.0 只有 schemaVersion 1，因此不存在旧版本升级路径，也不会猜测转换未知格式。

## 5. 失败与恢复建议

- “备份不能恢复”：按界面列出的第一项错误检查文件；不要手工删除字段来强行绕过验证。
- 校验和失败：重新从原设备导出；若只能保留损坏文件，请先复制原文件再尝试离线取证。
- 未来版本：在生成备份的较新 MouseKeeper 版本中使用，或升级当前应用。
- 浏览器下载被阻止：允许此来源下载文件，确认安全副本实际落盘后再恢复。
- 写入/配额失败：当前事务应保持原数据库不变；释放磁盘空间、关闭其他标签页并重试。
- 精确恢复前副本不能通过恢复预检：它可能忠实保留了恢复前数据库已经存在的不一致，属于取证/救援副本；保留原文件，并优先使用恢复前另行下载且验证通过的完整备份。
- 页面无法打开：不要清除站点数据。先备份浏览器配置目录，或使用浏览器开发者工具导出 IndexedDB 后再排查。

## 6. 备份保管

备份可能包含实验编号、研究说明和完整历史。仓库不会上传或加密它。建议：

- 使用操作系统全盘加密或加密归档；
- 至少保留两份、位于两个独立介质；
- 用日期和项目代号命名外部目录，不修改文件内部 JSON；
- 定期在非生产浏览器配置中做恢复演练；
- 不把真实备份提交到 Git、邮件公开群组或未经授权的云盘。

## 7. 已验证范围

Vitest 覆盖导出结构、canonical checksum、损坏/未来备份拒绝、引用审计、全表恢复、故障注入回滚和精确恢复前副本。Playwright 覆盖生产构建中的下载、修改数据、选择原备份、确认替换和恢复后计数回到原状态。真实大于 100 MB 数据、磁盘耗尽、Safari 配额和跨设备恢复仍未自动化。

## 8. Agent 恢复点

Agent 的恢复点与手工 JSON 备份用途不同。每条修改命令在第一个写能力执行前，会在同一个只读事务中读取 16 张业务表，并先把命令前状态持久化到独立 `mousekeeper-agent` 数据库；查询、导航和文件预览不读取全库快照。

命令完成后，系统比较一致的 before/after 状态。小范围变化保存逐行差分；达到 25 行、4 张表、512 KiB，或能力标记为高影响时保留完整 before。JSON 恢复、CSV 导入、永久删除和复杂批量路径使用完整恢复策略。整条命令中的多步共享一个恢复边界，后续工具失败但前面已经写入时仍会显示“失败但可撤回”。

撤回前会逐行确认当前值仍等于该命令产生的 after 值；若其他页面、标签页或后续命令已修改同一行，撤回进入冲突状态并停止，不会静默覆盖新数据。终态命令最多保留 200 条；这不是站点数据之外的灾难备份，清除浏览器站点数据仍会同时删除业务库和 Agent 恢复历史。
