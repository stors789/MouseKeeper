# MouseKeeper Agent

## 入口与工作方式

从侧栏或移动底栏打开“Agent”，也可以按 `⌘/Ctrl+J`。输入支持多行；Enter 执行，Shift+Enter 换行。执行中的命令可以停止，完成后可重试、编辑重发、打开受影响记录、查看技术详情，或撤回整条命令。

Agent 不是聊天问答层。模型只获得两个稳定工具入口：搜索 Capability Registry，以及按 capability ID 执行。它按需发现小鼠、笼位、繁育、实验、记录、任务、数据、设置、导航与视图能力，不会把整个 IndexedDB 塞入提示词。业务写入仍经过与图形界面相同的 `MouseKeeperService`、revision、幂等键、校验与事务规则。

明确且对象唯一的命令会直接执行。模型只有在对象无法唯一确定、找不到对象、缺少不可推断字段、指令矛盾或浏览器要求用户选择文件时才应询问或暂停。一个自然语言命令可进行多轮查询和连续写入；这些步骤共享一个 command ID 和恢复边界。

## 上下文

每次执行会提供：进入 Agent 前的页面路由、页面可见筛选/排序/分页、全部当前选择、浏览器语言、IANA 时区、当前时间、预设与模型。会话还按完整用户/助手/工具轮次保留最近消息和最近受影响实体，用于理解“它”“这些”“刚才的”。API Key、秘密请求头和业务全库不会进入这段上下文。

流式 Provider 会把文本增量立即显示在执行区；停止会终止响应体读取并隔离迟到的增量。历史超限可选择报错、丢弃最旧完整轮次，或生成不调用额外模型的本地确定性摘录。页面内最多渲染 40 条命令，持久恢复历史最多保留 200 条终态记录。

## 文件流程

JSON 恢复和 CSV 导入受浏览器用户手势限制。Agent 会先建立文件请求，结果卡显示真正的文件选择按钮；用户选择后，文件只保存在页面内存的临时 broker 中。Agent 必须先运行只读 preview，生成绑定同一文件的一次性 token；原指令明确要求恢复/导入时自动继续 commit，只要求预览时停止。JSON commit 会重新预检并额外下载恢复前安全副本。文件没有被选中前不会伪装成功。

## 恢复点与撤回

每条修改命令在首次写能力执行前读取 16 张业务表与可恢复的 MouseKeeper 偏好，并先持久化恢复点；只读命令不做全库快照。普通小范围变化保存逐行 before/after 差分；变化达到 25 行、4 张表、512 KiB，或能力明确标记为高影响时保存完整命令前快照。秘密存储键不在快照中。

“撤回整条命令”会先确认所有受影响行仍等于该命令执行后的值，再在事务中反向恢复。若之后有其他页面、标签页或命令修改了同一数据，撤回会进入冲突状态并停止，不会静默覆盖后来的更改。只读命令和没有状态变化的命令没有撤回按钮。

## 示例

- `M001 今天 22.4 克。`
- `把 A01 笼的全部小鼠转到 B03，然后打开 B03。`
- `找出超过 12 周且两周没称重的小鼠，给它们创建明天的称重任务。`
- `只显示未完成的逾期任务。`
- `导出全部小鼠 CSV。`
- `把默认模型的思考强度改成 high，超时设为 90 秒。`

## 评测边界

默认测试使用 deterministic provider，验证能力目录、参数契约、执行轨迹、数据库结果与恢复记录，不依赖收费 API。它不能等价证明任意真实模型对所有自然语言都能稳定理解。真实模型评测必须由使用者配置自己的 Provider 后单独运行，并记录模型版本、预设、日期和结果。
