# MouseKeeper 初始架构仲裁

> 仲裁人：主代理  
> 日期：2026-07-30  
> 输入：`00_project_inventory.md`、`01_product_architecture.md`、
> `02_data_model_review.md`、`03_ui_system_review.md`

## 1. 共同结论

- 当前是 greenfield 工程，无旧代码、数据或 Git 历史需要迁移。
- 产品是单人、本地优先的群体操作台，不引入登录、后端、云同步或重量级全局状态。
- 所有业务数据保存在 IndexedDB；localStorage 只保存主题、表格密度等 UI 偏好。
- 转笼、终止状态、创建后代、实验换组、软删除活动对象、完整恢复必须是事务命令。
- React 页面不能直接写 Dexie 表；唯一写入口是带 `operationId` 的服务层命令。
- UI 采用低饱和科研记录台方向、系统字体、本地 Lucide 图标、Assay Rail、桌面表格与移动卡片。

## 2. 冲突与裁决

### A-01 实体数量

需求清单实际包含 16 个实体而非 15 个。接受数据报告的计数：全部 16 张表均进入
schema、备份和恢复事务。

### A-02 当前笼位的事实来源

接受 `CageAssignment` 为唯一权威事实；同时接受数据报告提出的
`Mouse.currentCageId` 只读查询投影以支持 5,000 条列表性能。投影不可由普通表单编辑，
只能在同一转笼事务中更新；完整性扫描以活动 assignment 修复投影。

### A-03 体重与统一事件

需求既要求统一事件时间线，又单列 `WeightRecord`。裁决为：

- `WeightRecord` 是体重数值、单位、趋势和编辑的权威事实；
- 同一事务创建一条只读的 `MouseEvent(type=weight)` 时间线投影；
- UI 不允许分别编辑两份数据；编辑/软删除体重只能走同步服务命令；
- `eventId` 建唯一索引，完整性扫描检查一对一关系。

这保留统一时间线并避免两个可独立编辑的事实源。

### A-04 耳标重复

以数据安全优先，活动记录中的规范化耳标为硬唯一；导入不能以“仍导入”绕过。
软删除记录释放 `activeEarTagKey`，恢复时重新检查冲突。导入预览仍显示数据库内与文件内
重复，并允许用户修正或跳过该行。

### A-05 实验与繁育状态

`Mouse.status` 是单值操作状态，不作为关联事实。实验、繁育参与分别来自活动
assignment/pair。仪表盘分别计算，避免把“实验中”状态当作实验成员唯一依据。

### A-06 超出笼位容量

容量接近上限（默认 80%）为提示；超过最大容量为强警告，用户确认并填写原因后允许，
确认代码写入 ActivityLog。并发变化会使旧确认失效并重新提示。

### A-07 备份恢复

完整恢复只提供“替换当前数据库”，不做合并。解析、Zod 校验、版本迁移、checksum 和
引用审计在事务外完成；16 张表的 clear/bulkAdd 在一个 Dexie `rw` 事务中完成。恢复前
生成当前库备份；下载是否真正落盘必须如实提示。

### A-08 导航

桌面一级入口采用：总览、小鼠、笼位、繁育、实验、记录、任务、数据与安全、设置。
回收站属于“数据与安全”，不单独扩大一级导航。移动底栏固定为总览、小鼠、笼位、
任务、更多；复杂流程仍可在手机查看和执行，但明确提示桌面效率更高。

### A-09 PWA 工具链

依赖安装时 `vite-plugin-pwa` 的 Workbox 链出现已知高危开发依赖。拒绝保留该链，
采用本地 `manifest.webmanifest` + 原生 Service Worker。该方案必须通过实际离线重载、
更新缓存和安装清单验证后才能标记完成。

## 3. 实施边界

- `src/domain/`：实体、枚举、Zod schema、日期与规范化规则。
- `src/db/`：Dexie v1 schema、migration、完整性扫描。
- `src/services/`：事务命令、备份、导入导出、示例数据。
- `src/features/`：按业务模块组织页面、表单、查询 hooks；不得绕过 service 写数据库。
- `src/components/`：通用 UI 原语和应用壳。
- `src/test/` 与 `e2e/`：fake-indexeddb 单元/集成测试和真实浏览器闭环。

首版发布 v1 前不制造无意义的 schema v2；migration 机制与 fixture 必须存在，真正字段
变化时才提升 Dexie version。

## 4. 视觉基线

- 浅色：Porcelain `#F3F6F7`、Graphite `#182128`、Assay Teal `#0F6F6B`。
- 辅助：Protocol Indigo `#4459A8`、Signal Amber `#9B5C00`、
  Critical Carmine `#B42342`。
- 深色不是反相；背景 `#0E1519`、表面 `#141C21`。
- 页面标题不超过 24px、核心数字不超过 30px、普通容器圆角不超过 12px。
- 业务页面每个上下文最多一个实心主按钮；状态必须同时有文字和图标。
- 360px 无整页横向滚动；移动触控目标至少 44px。
- 不使用外部字体、远程图标、渐变 hero、卡片墙、卡通小鼠或无意义动画。

## 5. 第一条纵向验证路径

空库 → 建笼 → 建鼠并分笼 → 刷新仍存在 → 转笼 → 记录体重 →
创建任务并完成 → 导出备份 → 删除/修改数据 → 恢复备份 → 数据回到导出状态。

在该路径通过之前，不扩张装饰图表或次要偏好功能。

## 6. 当前未验证

上述均为设计裁决。真实 Dexie 事务、跨标签页、持久化、PWA 离线、截图、键盘、
大数据性能和恢复回滚尚未验证，必须在实现后由独立代理复审并追加证据。
