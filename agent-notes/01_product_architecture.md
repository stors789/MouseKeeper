# MouseKeeper 产品架构与信息架构审查

> 角色：个人实验动物管理产品经理 / 信息架构师  
> 审查日期：2026-07-30  
> 性质：实现前、需求级独立审查；未依赖其他代理结论  
> 结论状态：可作为首版范围、路由、页面和验收的产品基线，仍需数据架构与实际实现验证

## 1. 执行结论

MouseKeeper 首版应被定义为“单人、本地优先的小鼠群体操作台”，而不是缩小版 LIMS。用户每天需要完成的不是维护抽象主数据，而是围绕四类对象快速闭环：

1. 找到一只或一批小鼠；
2. 确认它们当前在哪里、处于什么状态；
3. 记录发生了什么以及下一步要做什么；
4. 能够可靠地备份、恢复和迁移全部记录。

首版导航应以“总览、小鼠、笼位、繁育、实验、记录、任务、数据与安全”为主，不建立用户、组织、审批、库存或分析中心。所有重要动作必须产生持久化结果和可追溯记录；跨表动作必须一次成功或一次失败，不能留下半完成状态。

最重要的产品裁决如下：

- `Mouse.currentStatus` 只表达单一“当前操作状态”；实验参与、繁育参与和笼位占用由各自关联记录表达，不能只靠状态推断。
- “活跃实验成员数”和“活跃繁育成员数”从活动关联记录计算；状态分布另行展示，避免重复或矛盾统计。
- 笼位占用以活动中的 `CageAssignment` 为事实来源；小鼠详情上的“当前笼位”是查询结果，不应成为第二套可独立编辑的事实。
- 体重以 `WeightRecord` 为事实来源；时间线合并展示体重记录，不再复制一条可独立编辑的 `MouseEvent`。
- 转笼、状态终止、批量创建后代、加入/退出实验、完整恢复均属于高风险闭环，必须有明确预览、事务边界、重复提交保护和失败反馈。
- 第一版可以分阶段开发，但对外称为“可用首版”前，需求中明确要求的各核心模块都必须达到闭环，不能用空页面、假按钮或 “Coming soon” 占位。

## 3. 核心人物与任务

### 3.1 唯一核心人物

**个人实验人员 / 小鼠群体记录维护者**

- 一个人同时承担日常操作、记录核对、数据备份和异常修正。
- 桌面端用于批量建档、复杂筛选、实验编组、导入导出和恢复。
- 手机端用于笼边查找、转笼、称重、状态修改、加事件和完成任务。
- 其容错重点是“不要丢数据、不要记错对象、操作后能确认结果”，不是权限与审批。

不应为“管理员、研究员、访客”建立角色，也不应出现登录、邀请成员、权限矩阵或团队工作区。

### 3.2 按频率和风险排序的用户任务

| 优先级 | 用户任务 | 成功定义 |
|---|---|---|
| P0 | 查找并确认小鼠 | 通过耳标、实验编号、名称、笼位等快速定位；详情显示最新状态、笼位和关键警示 |
| P0 | 建档、复制或批量创建 | 所有合法记录一次保存；重复和非法日期在提交前明确呈现 |
| P0 | 转笼 / 移出笼位 | 旧分配结束、新分配建立、容量处理和时间线记录保持一致 |
| P0 | 记录状态、事件和体重 | 写入后立即可见，刷新后仍在；异常只提示，不悄悄修改用户输入 |
| P0 | 备份和恢复 | 能预览、验证、生成恢复前安全副本，失败不会破坏现有数据 |
| P0 | 建立繁育组合并创建后代 | 父母、窝和后代自动关联，明显错误被阻止或显式确认 |
| P0 | 建立实验并编组 | 小鼠不能在同一实验的两个活动组中，退出仍保留历史 |
| P1 | 处理任务和到期事项 | 今日、即将到期、逾期清晰；完成与恢复均可追溯 |
| P1 | 批量修改和保存视图 | 选中范围明确，变更预览清楚，失败不会留下未知的部分状态 |
| P1 | 了解群体概况 | 指标可点击回到对应明细，图表帮助发现行动项而非装饰 |

## 4. 产品语义与跨模块裁决

这些裁决应先于页面编码，否则不同模块会各自解释同一概念。

### 4.1 小鼠状态

- 当前状态为单值枚举：存活、实验中、繁育中、预留、已转出、已死亡、已安乐死、其他。
- “实验中”和“繁育中”是用户可见的操作标签，但不替代实验/繁育关联；一只小鼠可以拥有实验历史和繁育历史，即使当前状态是“存活”。
- 仪表盘：
  - “存活小鼠”仅统计未删除且状态属于存活、实验中、繁育中、预留的记录；
  - “活跃实验成员”从未退出且实验进行中的 `ExperimentAssignment` 统计去重小鼠；
  - “活跃繁育成员”从活动繁育组合统计去重小鼠；
  - “其他”不计入存活，需作为待清理数据单列提示。
- 终止状态包括已转出、已死亡、已安乐死。切换到终止状态时，系统必须预览并默认关闭活动笼位分配、实验分配和繁育参与；用户取消则整次不写入。
- 在“添加事件”中选择死亡或安乐死，应进入同一状态终止流程，不能只写一条普通事件而保持小鼠仍“存活”。

### 4.2 标识和日期

- 内部 ID 自动生成、不可编辑、全局唯一；它是关联事实，不是主要展示名。
- 新建小鼠至少需要耳标号或实验编号之一；两者都为空时阻止提交。
- 耳标重复是高可见警告，不静默接受。首版默认阻止同一活动数据集中的重复耳标，但允许用户在导入预览中逐行选择“仍导入”，并记录确认；最终规则应由主代理与数据代理仲裁。
- 出生日期允许未知，但一旦填写不得晚于当前本地日期；年龄和周龄只从出生日期计算，不持久化为独立事实。
- 日期表示自然日，时间线动作使用带时区的时间戳；界面以当前设备时区显示，导出保留原时间戳。

### 4.3 删除与历史

- 列表默认隐藏 `deletedAt` 非空的数据；回收站按实体分组查看。
- 软删除不得级联删除历史事件、体重、笼位分配或实验分配。
- 删除有活动关系的小鼠时，必须显示影响清单，并通过一个事务关闭活动关系后再软删除；不允许仅从列表消失而仍占笼或留在进行中实验。
- 有小鼠的笼位禁止删除，先要求转笼或移出。
- 进行中的实验必须先结束或取消，之后才能软删除；历史事件保留，并显示已删除对象的名称快照。
- 永久删除只从回收站进入，二次确认中显示不可恢复的记录数量。引用仍存在时优先保留 tombstone，不做静默级联。

### 4.4 事实来源

| 用户看到的事实 | 唯一事实来源 | 禁止的重复来源 |
|---|---|---|
| 当前笼位 | 唯一活动 `CageAssignment` | 可独立修改的 `Mouse.currentCageId` |
| 活跃实验组 | 活动 `ExperimentAssignment` | 仅依赖 `Mouse.currentStatus` |
| 活跃繁育成员 | 活动 `BreedingPair` | 仅依赖 `Mouse.currentStatus` |
| 体重趋势 | `WeightRecord` | 同时可编辑的重复 `MouseEvent` |
| 年龄 / 周龄 | `birthDate` + 当前日期 | 持久化且可能过期的年龄值 |
| 笼位占用 | 活动 `CageAssignment` 数量 | 手工维护的 `Cage.currentCount` |
| 待处理 / 逾期任务 | `Task.status` + 到期时间 | 单独维护的计数 |

`ActivityLog` 记录“谁在本地应用中做了什么变更”，`MouseEvent` 记录“实验对象发生了什么”。二者用途不同，不应将所有表单保存都伪装成实验事件。

## 5. 导航结构

### 5.1 桌面

侧边栏按任务分组，保持一级入口稳定：

```text
工作台
  总览
  小鼠
  笼位
研究
  繁育
  实验
  记录
  任务
系统
  数据与安全
  设置
```

顶栏固定提供：

- 全局搜索（`⌘/Ctrl + K`，`/` 也可聚焦）；
- 全局“新建”菜单：小鼠、笼位、繁育组合、实验、事件、任务、快速称重；
- 当前页面标题与必要的面包屑；
- 主题切换放在用户可发现但不占主操作位的位置。

不要为“仪表盘、报表、分析”建立多个相似入口；总览承担行动摘要，记录承担事件与体重查询。

### 5.2 手机

底部导航最多五项：

1. 总览；
2. 小鼠；
3. 笼位；
4. 任务；
5. 更多。

“更多”包含繁育、实验、记录、数据与安全、设置。全局新增使用固定但不遮挡内容的加号动作；在小鼠详情中，该动作默认展开“加事件、称重、转笼、改状态、加任务”。

复杂 JSON 恢复和 CSV 字段映射可提示“桌面端体验更佳”，但不能显示假按钮；手机端仍应允许查看备份状态和导出完整备份。

## 7. 关键页面信息结构

### 7.1 总览

首屏顺序固定为：

1. 快捷新增与全局搜索；
2. 6 个可点击指标：存活小鼠、活动笼位、活跃实验成员、活跃繁育成员、待处理任务、逾期任务；
3. “需要处理”：逾期/即将到期任务、超容/接近容量、最近异常；
4. 最近新增或修改的小鼠；
5. 最近活动时间线；
6. “群体构成”一个区域，用性别、品系、状态、年龄四个页签切换，不同时铺开四张图。

每个指标必须链接到带对应筛选的列表。图表不提供无法落到明细的装饰性数字。品系只展示前 5 名和“其他”，并可查看完整列表。

### 7.2 小鼠列表

- 默认仅显示未删除记录，默认按更新时间倒序。
- 默认列：耳标/实验编号、性别、品系/基因型、年龄、当前笼位、当前状态、标签、更新时间。
- 内部 ID 不占默认列，但可复制并可在列设置中打开。
- 筛选条直接显示已生效条件及结果数，一键清除；保存视图只保存筛选、排序、列和密度，不保存数据快照。
- 勾选后出现有选中数和作用范围的批量操作条；“全选”必须明确是当前页还是全部筛选结果。
- 批量变更先预览影响，事务失败则整批失败；CSV 导入才允许“合法行成功、错误行失败”的部分成功语义。

### 7.3 小鼠详情

顶部摘要必须在无需滚动时显示：

- 主要标识、状态、性别、年龄、品系/基因型；
- 当前笼位；
- 终止状态或异常数据警示；
- 快捷动作：加事件、称重、转笼、改状态、加任务。

下方按“概览、时间线、体重、谱系、实验”分区。状态变化、转笼、加入/退出实验等系统事件只读；要修正时回到来源动作，避免直接修改一条历史而不改当前事实。

### 7.4 表单

- 新建小鼠分为“标识、基本信息、关系与位置、补充信息”，第一屏只要求完成最小必填字段。
- 不做长达十几步的向导；桌面用分区表单，手机用可折叠分区。
- 保存按钮旁说明将产生的关联动作，例如“保存并分配至 C-012”。
- 提交期间禁用重复提交；失败保留用户输入并将焦点移到首个错误。
- 离开有未保存数据的页面时，路由切换、刷新和关闭页均应尽可能提示。

## 8. 端到端核心流程

### F0 首次启动

1. 初始化空数据库后进入总览空状态。
2. 明确提示“数据仅保存在此浏览器；无云同步；请定期导出备份”。
3. 提供三条真实路径：创建第一个笼位、导入小鼠 CSV、生成示例数据。
4. 允许跳过引导并直接新建小鼠；笼位不是建档前置条件。
5. 成功产生第一条真实记录后，总览切换为实际数据视图。

完成标准：刷新页面后选择和记录仍存在；示例数据有明显标识。

### F1 创建小鼠 / 复制 / 批量创建

1. 用户填写至少一个人类可读标识。
2. 实时校验日期、枚举、父母关系和重复耳标。
3. 可选分配现有活动笼位；超容需额外确认。
4. 复制时只带入品系、基因型、来源、毛色、标签等模板字段，不复制内部 ID、耳标、实验编号、事件、体重和当前笼位。
5. 批量创建使用共享字段 + 逐行标识；提交前逐行预览。

完成标准：合法数据持久化并出现在列表；批量建档要么整批成功，要么不写入，错误定位到具体行和字段。

### F2 转笼 / 移出

1. 从小鼠详情、笼位详情或列表批量动作进入。
2. 显示来源笼、目标笼、移动数量、目标容量和生效时间。
3. 若达到容量的 80% 显示提示；超过最大容量显示强警告，要求再次确认并填写简短原因。
4. 一个事务中结束旧分配、创建新分配、更新活动日志和时间线。
5. 移出但不进入新笼时，目标为“未分配”，仍记录结束原因。

完成标准：任一小鼠最多一个活动笼位，源/目标笼计数与历史一致；刷新后不反弹。

### F3 繁育到后代

1. 建立组合，父本选择器默认只列雄性，母本默认只列雌性。
2. 性别未知或不符合时显示明确警告并要求确认；终止状态父母同样警告。
3. 阻止自我父母、明显循环谱系和子代出生早于父母；重复活动组合提示。
4. 在组合中添加窝，记录出生、出生数、存活数、断奶日期。
5. “创建后代”按存活数生成行，自动带入父母、窝号和出生日期；用户补充标识、性别、基因型和可选目标笼。
6. 预览后原子提交后代和关联。

完成标准：后代详情可返回父母与同窝记录，父母详情可看到直接后代；失败不产生孤立小鼠。

### F4 实验建组到退出

1. 新建实验并至少创建一个自定义组。
2. 首版规定同一实验内的组互斥：每只小鼠最多一个活动组。
3. 候选选择器显示状态、笼位和关键条件；重复加入阻止，终止状态加入进行中实验需显式确认。
4. 加入后小鼠详情与实验详情双向可见，但不强制改写 `currentStatus`。
5. 退出需记录日期和原因；将小鼠移到另一组时先关闭旧分配，再建立新分配。
6. 结束实验时预览并关闭所有活动分配，保留历史。

完成标准：任何时点同一小鼠在一个实验最多一个活动组；删除/结束不会静默丢失历史。

### F5 事件与快速称重

1. 从小鼠详情加单条事件，事件类型决定扩展字段。
2. 从快速称重页选择一批小鼠，逐行输入数值、单位和可选备注。
3. 异常值提示依据同一小鼠最近有效体重和合理范围，只提示，不阻止保存。
4. 保存后显示每只小鼠结果和相邻变化；体重趋势从 `WeightRecord` 读取。
5. 批量事件可创建每只小鼠一条独立记录，并共享 `batchId`，便于单只时间线与整批追踪。

完成标准：小鼠时间线、记录中心和体重趋势指向同一事实，不出现两份可分别编辑的数据。

### F6 任务

1. 可从全局新增或任一对象详情创建，并预填关联对象。
2. 任务进入今日、即将到期或逾期分组。
3. 一键完成后立即持久化并提供短时撤销；已完成列表支持恢复。
4. 浏览器通知只在用户主动开启时请求权限；被拒绝时应用内提醒继续工作。

完成标准：关闭或刷新后任务状态不变，关联对象删除后仍以 tombstone 名称可追溯。

### F7 搜索、筛选与保存视图

1. 全局搜索按小鼠、笼位、实验、事件分组返回，命中字段高亮。
2. 进入小鼠列表后可组合性别、状态、品系、基因型、笼位、实验、标签、出生/年龄和删除状态。
3. 当前条件以可移除的筛选标签显示。
4. 保存视图包含名称、筛选、排序、列可见性和密度；删除视图不删除业务数据。

完成标准：从结果进入详情再返回时保留搜索/筛选上下文；空结果给出清除条件和新建入口。

### F8 软删除、恢复和永久删除

1. 删除前显示关联影响；有活动关系时要求先关闭，或选择“关闭关联并删除”。
2. 软删除后从默认列表消失，进入回收站。
3. 恢复前重新检查编号、耳标和活动关联冲突；冲突未解决时不能静默恢复。
4. 永久删除要求二次确认，显示不可恢复的记录数量。

完成标准：历史引用不因父对象删除而崩溃；恢复不会创造重复活动分配。

### F9 完整备份与恢复

1. 导出包含 schemaVersion、appVersion、exportedAt、全部业务表、设置和必要元数据的 JSON。
2. 恢复先离线解析和校验，展示版本、时间、各实体数量、错误/警告以及将被替换的当前数量。
3. 确认前自动生成当前数据库安全备份并触发下载；明确告知浏览器无法证明文件已被用户妥善保存。
4. 首版完整恢复语义为“替换当前数据库”，不做含糊的合并。
5. 使用验证后的暂存数据和事务写入；任何写入失败都回滚并保留原库。

完成标准：损坏、缺字段或未来 schemaVersion 的文件被拒绝；失败后当前数据仍可用。

### F10 CSV 导入与导出

1. CSV 导入仅面向规范化小鼠数据；选择文件后展示编码、列和前若干行预览。
2. 字段映射页区分必需、可选、未知列，并可下载示例 CSV。
3. 逐行校验空值、非法日期、未知枚举、重复 ID/耳标和缺失父母/笼位关联。
4. 用户确认后，将所有合法行作为一个事务写入；错误行不写入。
5. 结果报告明确成功数、失败数、警告数和逐行原因，可下载错误报告。
6. 小鼠、笼位、实验、体重和事件分别导出 CSV，防止形成难以理解的“万能表”。

完成标准：部分成功是可解释的“合法行全部成功、错误行全部失败”；数据库写入失败时合法行也整体回滚。

### F11 示例数据

1. 空状态可生成一套覆盖全部核心模块的小型示例。
2. 所有示例实体和由其衍生的关联均标记 `isSample` 或可追踪至示例批次。
3. 删除示例数据前显示将删除的各实体数量；仅删除示例数据，绝不按名称或日期猜测。

完成标准：真实数据和示例数据混用后，一键删除示例不会误删真实记录，也不会留下孤立关联。

## 9. 首次使用路径

不使用强制多页 onboarding。首次空库总览直接提供：

1. **本地数据说明**：一句话解释数据保存在当前浏览器，并提供“了解备份”链接；
2. **首要 CTA**：“创建第一个笼位”；
3. **替代路径**：“导入 CSV”与“使用示例数据体验”；
4. **可跳过入口**：“直接创建小鼠（暂不分配笼位）”。

创建笼位成功后，成功页仅提供三个下一步：新增一只小鼠、批量新增、返回总览。创建第一只小鼠后，详情页突出“记录体重、添加事件、创建任务”。

非阻断提醒：

- 真实记录达到 10 条且从未导出备份时，在总览显示备份提醒；
- 首次完成一次完整备份后记录 `lastBackupAt`，此后按距上次备份时间提示；
- PWA 安装和通知授权只在设置或相关功能上下文中出现，不在首次启动时连续弹窗；
- 示例数据始终有“示例”标记，并在总览提供“删除全部示例数据”入口。

## 10. 功能优先级与首版范围

### 10.1 P0：首个可验证纵向闭环

以下内容必须先完成，任何一个缺失都不能称为可用内部 Alpha：

- IndexedDB 版本、迁移、事务服务、软删除、错误处理；
- 空库启动和示例数据；
- 小鼠单条建档、编辑、详情、搜索、状态、软删除；
- 笼位建档、活动分配唯一性、转笼和容量警示；
- 繁育组合、窝、原子批量创建后代；
- 实验、组、加入/退出和互斥规则；
- 单条事件、快速称重、体重趋势；
- 任务创建、完成、恢复和逾期；
- 完整 JSON 备份、校验、替换式恢复；
- 小鼠 CSV 预览、映射、错误行隔离与结果报告；
- 核心 CSV 导出；
- 手机端能够完成查找、转笼、称重、事件、状态和任务；
- 刷新与重启持久化、重复提交保护和核心 E2E。

### 10.2 P1：首版交付前补齐

这些可以晚于第一个纵向闭环实现，但在最终宣称满足需求前仍须完成：

- 复制小鼠、共享字段批量建档；
- 小鼠批量状态、批量转笼、批量标签增删；
- 完整组合筛选、保存视图、紧凑表格和大列表策略；
- 全局跨实体搜索；
- 仪表盘群体构成、最近活动、异常和容量模块；
- 记录中心及事件筛选；
- 笼内性别、年龄、品系/基因型概览；
- 浏览器本地通知的优雅降级；
- 回收站永久删除与冲突恢复；
- 深色模式、键盘、焦点、Skeleton、长文本和窄屏打磨；
- PWA 离线安装与更新提示；
- 全部规定单元/E2E、5,000 小鼠和 50,000 事件数据量验证。

### 10.3 P2：可选增强，不得阻塞首版

- 最近一次批量操作的有限撤销；
- CSV 导入映射模板；
- 更细的异常阈值个性化；
- 可打印的小鼠/笼位摘要；
- 跨实体的更多批量事件类型。

### 10.4 明确不做

除需求已明确排除的多用户、登录、权限、云同步、服务器、审批、电子签名、法规认证、AI、RFID、采购库存、LIMS 集成、原生移动端和无限代谱系图外，首版还不做：

- 自定义字段设计器或可编程工作流；
- 递归任务、日历同步、邮件/短信推送；
- 附件、照片和大文件存储；
- 统计检验、样本量计算、图表编辑器；
- 多语言和多时区协作；
- 可拖拽无限画布谱系；
- 二维码硬件扫描与标签打印；
- “合并式完整恢复”；只提供明确的替换式恢复；
- 为少量状态引入全局状态管理或事件总线；
- 没有真实动作的导出、筛选、菜单项或仪表盘卡片。

## 12. 可执行视觉与交互约束

这些约束控制产品密度，具体色值由 UI 系统报告决定。

- 桌面侧边栏建议 232–248px，可折叠；主内容流体宽度，复杂表格允许横向滚动而非挤压到不可读。
- 页面头部最多一个主按钮；其他动作进入次按钮或菜单。危险动作不与主保存并列同色。
- 顶部指标最多 6 个；可视区域同时出现的图表不超过 2 个，群体构成用页签切换。
- 只有真正独立的区域使用卡片；列表、筛选和页签不逐层套卡片。
- 桌面普通表格行高约 44px，舒适模式约 52px；手机触控目标不小于 44×44px。
- 移动端 `< 768px` 不渲染缩小表格，改为卡片；批量选择后底部固定操作条必须避开系统安全区。
- 表单对话框设置视口高度上限并让内容区滚动；保存/取消保持可见。
- 每个状态同时使用文字和图标/形状，不只依赖颜色；危险、警告、成功颜色全局语义一致。
- 一次操作只显示一个明确结果 Toast；失败 Toast 必须包含可执行下一步，详细错误放在可展开区。
- Skeleton 只模拟最终结构；空状态必须有原因、下一步和可用入口，不能只放插画。
- 长耳标、基因型、备注和中英混排必须截断但可查看全文；内部 ID 提供复制，不强塞进每张卡片。
- 深色模式保持医学/科研工具的低眩光对比，避免纯黑大面积背景和高饱和霓虹状态色。
- 主色只承担选择、链接和主动作；状态色不得替代信息层级。
- 键盘焦点始终可见；关闭对话框后焦点返回触发按钮；列表常用动作可通过 Enter/Space 执行。
- 图表必须有文字摘要、图例和可点击明细；没有行动价值的数据用数字或列表，不强行作图。

### 12.1 页面级视觉验收

| 页面 | 必须一眼看清 | 不允许 |
|---|---|---|
| 总览 | 今天要处理什么、哪里超容、群体规模 | hero、欢迎大图、四处重复指标 |
| 小鼠列表 | 当前筛选、结果数、标识、笼位、状态、选中范围 | 手机缩小表格、隐藏已生效筛选 |
| 小鼠详情 | 这是谁、在哪里、当前状态、下一步动作 | 用十几张同等权重卡片铺满 |
| 笼位详情 | 当前占用/容量、笼内鼠、转笼入口 | 只显示静态容量环而无明细 |
| 繁育详情 | 父母、关键日期、窝、创建后代 | 首版无限代谱系画布 |
| 实验详情 | 组别、成员、状态、加入/退出 | 用统计分析占据核心位置 |
| 快速称重 | 当前输入对象、上一体重、异常、下一行 | 每只鼠都弹一次对话框 |
| 备份恢复 | 文件版本、数据量、替换影响、失败原因 | 单击即覆盖、只 Toast 不给报告 |

## 13. 给数据与实现决策的硬约束

### 13.1 原子业务动作

| 动作 | 必须在同一业务事务内完成 |
|---|---|
| 转笼 | 结束旧 assignment、建立新 assignment、写系统事件/活动日志 |
| 状态终止 | 更新状态、写状态事件、关闭笼位/实验/繁育活动关系 |
| 创建后代 | 创建全部 Mouse、关联父母与 Litter、可选建立笼位分配、写活动日志 |
| 实验换组 | 结束旧 assignment、建立新 assignment、写退出/加入记录 |
| 软删除有活动关系的小鼠 | 关闭活动关系、设置 deletedAt、写活动日志 |
| 删除示例数据 | 删除/软删除同批次全部示例关联，任何失败整体回滚 |
| CSV 合法行提交 | 所有合法行一次提交；数据库错误则全部回滚 |
| 完整恢复 | 校验通过后替换全部表和设置；任何表失败则恢复原状 |

### 13.2 其他实现边界

- 所有写操作使用一次性 operation ID 或提交锁，防止快速连续点击重复创建。
- 软删除记录默认不参与唯一性和活动统计，但恢复时必须重新校验冲突。
- 活动关系应有明确的开始/结束时间；“活动中”不能靠缺少任意字段猜测。
- 系统生成的状态、转笼、实验加入/退出事件不可直接编辑；通过来源动作修正并留下新的活动日志。
- 自定义事件扩展字段必须按事件类型校验，未知字段在备份迁移时保留或明确报告，不能静默丢弃。
- 备份包含软删除数据、关联、设置和元数据；CSV 是交换格式，不是完整恢复格式。
- 恢复不能把未来 schemaVersion 当作当前版本尝试导入。
- 缺失关联在导入预览中明确显示；允许保留的历史孤儿必须以 tombstone 呈现，而不是导致页面报错。
- 保存视图只存查询配置，不存查询结果；主题与表格偏好可放 localStorage，业务事实必须在 IndexedDB。
- 所有列表和总览的数量都必须可追溯到明确过滤规则；不允许同一指标在不同页面口径不同。

## 14. 不确定项与默认处理

这些问题不应阻塞初版开发，除非主代理掌握更明确领域证据；当前默认如下：

| 不确定项 | 当前默认 | 何时需要重新裁决 |
|---|---|---|
| 耳标是否绝对唯一 | 活动数据默认唯一；导入可显式确认重复 | 用户真实数据证明耳标会按房间/批次重复 |
| 实验与繁育能否同时参与 | 可以，关联独立；状态仍只有一个 | 领域规则明确禁止并行参与 |
| 超容量能否保存 | 强警告 + 二次确认 + 原因，允许紧急情况 | 用户要求成为硬阻断 |
| 一窝可创建后代数 | 默认不超过当前存活数 | 用户需要补录历史且计数不完整 |
| “其他”是否算存活 | 不计入存活并提示清理 | 增加独立生命状态字段后 |
| 实验组是否都互斥 | 首版同一实验内全部互斥 | 出现多因素/交叉分组真实需求 |
| 完整恢复是合并还是替换 | 仅替换 | 未来有经过设计的去重合并工具 |
| 提醒周期 | 无递归任务，仅单次到期时间 | 首版上线后证明递归任务是高频刚需 |

## 15. 首版产品验收门

只有同时满足下列条件，产品层才允许称为“首版核心流程闭环”：

- 新用户可从空库创建笼位和小鼠，也可导入或使用示例数据；
- 小鼠、笼位、繁育、实验、事件/体重、任务均能完成至少一个真实端到端流程；
- 每个详情页都能返回其来源列表，并保留筛选/搜索上下文；
- 状态终止、转笼、繁育后代、实验编组在刷新后保持一致；
- 软删除、恢复和永久删除有清楚影响提示，不破坏历史页面；
- JSON 可完整导出、合法备份可替换式恢复、损坏/未来版本备份被拒绝；
- CSV 导入有预览、映射、错误行隔离和结果报告；
- 手机宽度可查鼠、转笼、称重、改状态、加事件和完成任务；
- 所有可见按钮都有实际行为，所有失败都给出原因和下一步；
- 仪表盘口径与列表过滤结果一致；
- 没有把需求中的明确必需功能藏在占位页或“稍后实现”菜单中；
- 以上结论由实际运行、刷新/重启、单元测试和 E2E 验证，而不是只看代码。

## 16. 交接建议

主代理整合数据与 UI 报告时，优先仲裁四个问题：

1. 终止状态如何原子关闭笼位、实验和繁育关系；
2. 恢复前安全备份与替换式恢复的具体事务方案；
3. 耳标重复策略和导入覆盖范围；
4. `ActivityLog`、系统事件与用户事件的只读/可编辑边界。

若实现阶段为了赶进度需要缩小内部 Alpha，先减少图表、通知、保存视图和次要批量便利，不得削减备份恢复、跨实体一致性、核心闭环或错误反馈。
